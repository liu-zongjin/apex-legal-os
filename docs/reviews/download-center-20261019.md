# 下载中心审查与修复 · 2026-10-19

恢复基点：`2211db1`。工作分支：`codex/download-center-audit-20261019`。

## 已修复的问题

- 部分页面绕过统一下载登记：补充直接下载链接、离屏链接点击，以及研究、系列案件和费用导出按钮。已登记的文件链接和原有大卷宗流式下载继续走原通道。
- 案卷生成后未点击下载时不可见：从归档版本和案件绑定目录读取已生成的 PDF、目录、办案小结和清单，保留真实案件和生成时间。
- 仅凭文件存在就显示可打开：加入授权目录检查，区分原文件缺失、目录不可用、位置未确认和批次汇总。
- 前端重新按时间排序会覆盖服务端大小顺序：改为服务端对全部匹配记录筛选、排序后分页，未知大小排最后。
- 加载期间的新筛选被忽略：记录待执行的刷新请求。
- 浏览器旧记录超过单批 200 条时可能漏导入：分批完成导入后再清理浏览器旧数据。
- 用户取消系统保存被显示为失败：新增取消状态，避免计入待处理失败。
- 新版本资源可能被离线缓存遗漏：同步更新主页面、案件页面、共享下载脚本和离线缓存版本。

## 清理行为

分析仅检查记录，不修改文件。批量清理仅针对已选择、当前再次核实缺失且不在处理中的记录；案件原始数据库不被删除。无法确认的目录和未知位置保留。文件大小读取磁盘实际字节数；日期使用北京时间的下载／生成起日与止日，止日包含整日。

移到废纸篓需要勾选文件并在界面确认，每批最多 100 个。服务端按记录 ID 校验授权目录和文件版本，拒绝正在处理、已变化或符号链接文件。部分失败会保留错误结果。测试未移动任何真实用户文件。

## 验证

- 后端下载中心 18 项匿名临时数据测试：大小排序跨页、未知大小、时间边界、历史归档、清理复核、变化文件、符号链接、原有下载行为。
- Chrome 与 WebKit：来源筛选、大小／日期请求、整页勾选、取消与确认、缺失记录分析清理、离屏导出、流式字节、原生保存回传、深浅色及窄屏布局。
- 全仓扩展检查：语法、接口契约、敏感信息、共享能力、隔离数据库自动测试。

真实邮箱／法院网络下载、系统保存面板和 Finder 移到废纸篓未使用真实业务文件执行。历史上没有登记且没有保存路径的浏览器下载不能可靠恢复其原位置，仍标注为位置未确认。
