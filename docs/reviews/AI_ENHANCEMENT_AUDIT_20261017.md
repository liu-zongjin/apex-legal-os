# AI 增强审查与修复记录（2026-10-17）

本轮覆盖直问/联网问答、模型调用与降级、流式传输、任务恢复与停止、历史保存、Skill、长期记忆与上下文、案件与本地文件问答、制品预览及导出、程序缓存更新。

## 现场核验与定位边界

- 只读核验最近失败任务的服务端进度：三次原始错误均为输入预算超限；界面后两次只显示“原问答任务未能完成”，隐藏了实际原因。
- 相同模型在不附加 Skill 的直接请求中能正常回答，说明简短问题和模型连通性本身不是充分的失败原因。已保存历史没有保留旧请求的完整 Skill 选择，不能把每次历史超限都唯一归因于网页正文或某个 Skill。
- 原实现允许五份网页各携带约 18,000 字正文；所选 Skill 可注入约 30,000 字；文件问答最多拼接 18 段、每段约 3,500 字。这些上限都未与应用的保守预算统一分配。
- Skill 列表未加载时，仍可能发送已保存的选择，而按钮只显示“Skill”，使额外输入不明显。本轮增加选择可见性、有效性校验和专门错误提示。

## 确认的问题与修复

| 优先级 | 问题 | 修复后的行为 |
| --- | --- | --- |
| P1 | 联网资料与回答预留空间分别计算，大正文导致短问题超限 | 先核算必需指令和回答预留，再分配网页空间；本地提取相关原文、网址/段落去重，不增加摘要模型调用 |
| P1 | 流式终止错误被当成断线，恢复后丢失真实原因 | SSE 错误携带状态并直接保存具体原因；真正断线才查询原任务；恢复也保留原错误事件 |
| P1 | HTTP 200 即被当成取消成功，即使 JSON 表示任务不存在 | 只接受 success=true；未确认的停止继续核对原任务，不误写“已停止” |
| P1 | 上游没有结束标记就断流，半截文字可能被视为完整回答 | 必须有 finish_reason 或 DONE；协议中断及无效回答结构进入原有备用链 |
| P1 | 文件问答按固定大段数拼接，容易超过预算；可能只覆盖排名靠前的文件 | 细化原文片段并按预算选择；先确保每个所选文件都有片段；不能全部覆盖就明确提示分批，不静默遗漏文件 |
| P1 | 文件路由的 HTTP 异常被框架转换后，完成回调读不到异常，恢复状态可能停在 received | 文件问答封装直接写入失败/取消进度，再交给框架返回响应 |
| P2 | 持久化 Skill 选择可能隐藏或已失效；超长规则只有笼统错误 | 保留“已选 Skill”状态，发送前校验；超限直接提示切换或取消 Skill |
| P2 | 生成中删除消息或重新生成，会破坏本轮问题或覆盖输入草稿 | 当前对话仍生成时阻止这两类操作；其他对话仍可正常使用 |
| P2 | 浏览器缺少流式读取能力时只能进入异常恢复 | 能力检测失败时使用原有完整回答接口 |
| P1 | 联网规划沿用长回答超时，网页抓取之前可能等待数分钟 | 规划限制为 8 秒与 450 输出 token；超时使用本地关键词，保留指定域名/API 名和必要续问对象 |
| P2 | 身份、问候等问题还可能发生规划和网页检索 | 对狭窄、完整匹配的无需外部事实请求跳过检索规划；涉及价格、文档等外部信息仍按原路径检索 |

## 联网 token 优化原则

1. 保留完整问题与必需规则，先留出回答空间。
2. 从全文筛选相关段落，避免只截页面开头；保留表格的行标签、单位、数值，以及紧随结论的限制语句。
3. 简单、一般、多要点问题分别使用约 4 / 7 / 12 KB 的 UTF-8 原文空间上限，并进一步受当前请求剩余空间约束。这里是保守输入计量，不是服务商真实账单 token。
4. 相同网址、相同原文段落只提交一次；来源编号仅对应实际进入证据包的内容。
5. 页面提供的日期字段与抓取时间分开保留；未覆盖全部检索要点时明确提示资料不足。
6. 搜索规划有独立短超时；失败时本地生成查询，避免反复付费规划及长时间等待。
7. 压缩完全在本地完成，不额外付费调用摘要模型。身份/问候问题还可省去规划调用。

文件问答同样明确标注“相关原文节选”，不把有限检索冒充全文审阅。完整审阅超大材料应按文件或章节分批。

## 尚未由本轮验证覆盖的边界

- 未逐个进行所有服务商的真实计费请求；服务商特有的网关、额度或账户权限仍以实际返回为准。
- 普通网页的相关性筛选不等于权威法律全文核验。特别长的权威报告、超长 Skill 或要求逐字审阅的整批材料仍可能需要分批，不能承诺任意长度输入均一次完成。
- token 降幅随网页及问题变化；本轮没有以真实账单声称固定百分比降幅。
- 保留旧失败记录，不修改或伪造历史回答。修复后的错误将携带可追查的实际原因与输入计量。
