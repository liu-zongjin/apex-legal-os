# 移动端 Stella 品牌修复

## 原因与实施

移动清单和图标仍使用旧 APEX 资源，默认启动图片也未更新。桌面上传品牌仅存在当前 WebView 的 localStorage，另一设备和域名无法读取。旧移动应用壳与图片缓存又延长了旧资源的生命周期。

- 默认品牌与各尺寸安装图标改为 Stella；现有自定义品牌保持优先。
- 本机启动及设置上传、恢复默认、应用历史品牌时，将有效 PNG/WebP 同步到忽略的 `data/mobile-brand.json`。写入验证完整图片并原子替换，失败不破坏现有品牌。
- 手机同步品牌状态与图片，保留本机最近品牌以支持离线启动；重新联网和返回前台时再次读取。
- 手机启动页及独立案件入口增加品牌标识，深色使用既有共享品牌适配器；桌面 Dock 的实时替换流程保留。
- 清单名称更新为 Stella，保留安装 ID 与 `/case-manager` 启动地址。应用壳升级 v230，品牌图标使用白色方形画布，交由手机系统裁切圆角。品牌清单和图片重新验证缓存。
- 品牌读取不包含案件数据，写入仍须登录；未扩大业务接口公开范围，未清理案件 IndexedDB 或待同步操作。

## 实际验证

- 扩展检查通过，595 项测试。新增测试覆盖跨请求持久化、无效上传保留原品牌、重置、损坏配置、图标尺寸和白色画布，以及公开读取但未登录写入返回 401。
- 匿名 Chrome 390×844 场景通过：新设备同步、离线恢复、浅色/深色启动标识、恢复默认、图片加载及无横向溢出；品牌观察器未发生请求循环。
- 通过 Tailscale 私有 HTTPS 实际读取当前清单、品牌状态和 180×180 安装图标。清单为 Stella，动态图标显示与桌面当前品牌一致的黑色文字和红色末字母。
- 新入口登录页返回 HTTP 200。未在实体 iPhone 或 Android 手机上执行安装。

## 已安装入口

页面启动品牌联网后可同步。旧应用壳若刚完成后台更新，可关闭后重新打开，或用 Safari 打开最新网页入口。

iOS 主屏幕图标及系统启动快照由系统保存，网页不能保证立即替换。需要更新时，在 Safari 中重新「添加到主屏幕」；先保留旧入口，以免影响旧入口的离线资料与尚未同步操作。无需清空浏览器数据或删除案件缓存。
