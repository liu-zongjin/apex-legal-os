# Safari 桌面 App 启动专项修复 · 2026-10-07

## 根因与修复

v231 仍以独立案件页面作为安装启动地址，并把主页缓存准备设为可失败步骤，依赖登录及已有缓存才接回主界面。新桌面 App 的独立存储环境不能满足这个前提，可能只显示案件壳而没有全局悬浮导航。

- 保留 manifest id `/case-manager`，启动地址改为 `/`。
- 旧独立桌面入口在首次页面启动、尚未由 Service Worker 控制时，也进入 `/?workspace=cases`。判断同时支持 iOS `navigator.standalone` 和标准 display-mode；iframe 不跳转。
- 公开不含业务记录的 `/app-shell` 和必要静态源码资源；应用壳 v232 必须完整准备主界面后才能激活，不依赖 Safari 存储或登录 Cookie。根页面与所有业务 API 继续检查登录。
- 案件 iframe 登录过期时让整个同源父 App 打开登录页，登录后回到主标签容器。
- 不删除案件/文章 IndexedDB、待同步操作、品牌或目录偏好，也不新增另一套底部导航。

## 实际验证

`tests/mobile_standalone_browser.js` 使用独立匿名 HTTP 服务、390 × 844 Chrome、真实 Service Worker 和全新存储；模拟独立运行标志。

1. 无 Cookie、无缓存打开旧案件地址：显示登录而不是案件离线页。
2. 在 App 内登录：主界面与完整主页缓存正常建立。
3. 清除测试会话 Cookie 后打开案件 iframe：整个 App 转到登录。
4. 再次登录并断网，从旧案件入口进入主标签容器；内嵌页面不循环跳转。
5. 原有悬浮导航可见，位置 x10/y778/宽370/高58；点击主页、断网刷新后再返回主页均成功，页面无未捕获异常。
6. 未登录也可通过公共 UI 安装完整缓存；登录 HTML 不进入缓存；未完成资源下载不发布主页标记。
7. 服务测试证明 `/app-shell` 和源码可读取，而根页面保持登录入口，案件 API 仍返回401。
8. 扩展检查596项通过，接口契约753条，增加1条公共 UI 路由。

## 限制与升级

本机 Playwright WebKit 下载成功，但浏览器进程启动超时，未完成 WebKit 引擎操作验证，也没有实体 iPhone 验证。既有桌面 App 需联网加载一次新版后完全退出重开；会话缺失时在该 App 内登录。保留原图标及本机缓存，不要求删除后重新安装。
