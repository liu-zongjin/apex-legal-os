# 事实核对与证据册：实现与审查记录

日期：2026-10-14。恢复基线：16f1aac39ec55468a70b0d8126ec391a3cd88b90。

## 实现

案件详情和右键菜单进入工作台，复用案件选择器与本地文件浏览器。
事实核对支持粘贴文字或案件内草稿文件、所选材料、AI逐条初核、可验证逐字引句、
页/段/工作表定位、律师复核及 Word/Excel/Markdown/JSON 成果版本。
证据册支持证据标题、证明目的、顺序确认、PDF/图片/Word编册、页码和书签、
Word/Excel目录以及固定原件SHA256的页码映射。原件和案件状态均不改动。

任务元数据及成果落入绑定案件文件夹的 Stella办案成果/<任务ID>，原子保存；
无需数据库迁移。运行时采用单进程持久任务记录和一条重型办理队列，
不是支持多个服务器worker的分布式调度器。

## 差异与代码审查

本次逐段人工代码审查并用针对性测试、真实浏览器及渲染验证，不声称独立第三方审计。
审查覆盖新增服务、接口、任务恢复、文件路径、共享PDF装配、iframe协议、宿主导航、
页面状态与原有归档消费者；未变更原案件/客户数据源和既有AI问答协议。

发现并修复：

- Python 3.8不支持asyncio.to_thread；改用仓库既有线程适配，并延后初始化队列信号量。
- 混合PDF可能被整份平均文本量误判；事实核对逐页检查，未识别页不静默跳过。
- 旋转/裁剪PDF的可见方向可能改变；归一化时保持源页视觉方向，八种角度/裁剪组合做像素对比。
- 模型可能引用不存在的句子；仅接受候选片段中确实存在的引句，无有效引句不能标初核支持。
- 并行或同名输出覆盖；任务ID与版本目录独立，历史版本可下载。
- 材料更换后引用、恢复或复核出件可能沿用旧内容；原件hash与当前案件绑定复查。
- 用户输入能覆盖证据源hash等元数据；证据条目仅接受路径、标题和证明目的字段。
- Excel空列/公式缓存丢失语义；xlsx读取保留单元格坐标及公式/缓存状态。
- 未完成任务可以提前编辑复核；办理期间复核控件禁用。
- 未保存意见被切案或切任务丢弃；要求先保存，轮询不覆盖正在编辑的复核意见。
- 暗色子面板不随父页面变化、下载链接对比不足；同步主题并提高对比。
- 停止后台线程时清理与写入竞争；线程仅写独立暂存区，停止后不发布并由写入者清理。
- 立即停止尚未开始的任务可能传播CancelledError；取消入口捕获并持久化停止状态。
- 隐藏页面持续轮询；主工作区与嵌入材料浏览器均暂停后台刷新。
- 超过材料限额时前端可能静默截断；拒绝超量加入并提示，服务端也校验。
- 任务时间显示UTC日期；界面统一按Asia/Shanghai显示。

## 第二轮审查与调试

- PDF页面引用重绘可能遗漏可见批注和表单值。共享装配器在插入前和编号前均flatten私有内存副本；像素一致性覆盖实际插入和编号链路，原件保留批注及表单。最低PyMuPDF版本1.24.2；旧版遇到批注明确失败。
- 原先只有原件hash，没有独立输入副本。现在创建任务复制到私有inputs目录，复制后和读取前核验hash；只解析固定副本。继续办理沿用固定解析底稿并校验hash，避免OCR再解析改变引用编号。发布/继续/复核/查看原文仍检查当前原件，变化须新建任务。
- 交办新任务前要求保存人工复核；移出核对材料和草稿文件前捕获目录编辑，避免重绘丢失标题及证明目的。
- 工作台采用玻璃导航、分段切换、实体内容卡片、原文引用区和独立成果按钮；验证明暗外观、响应布局，提供降低动态与透明度设置。
- 近期旧分支的标签折叠、分类计数、编辑器、回收站、Dock图标等，已由后续整合提交进入main；不再次覆盖较新的主线实现。

最终扩展检查通过（780项回归测试），其中16项工作流专项测试通过；真实浏览器匿名闭环通过。产物位于工作区outputs/stella-workflow-review-20261014，不入Git。AI语义准确率、真实云OCR和原生WKWebView仍未实测。

## 文书驱动的事实核对与证据编排升级

根据用户明确的业务流程调整：定稿法律文书是证据编排的依据。新增证据编排草案阶段，
先解析文书事项并匹配原文，再拟定名称、证据摘要和证明内容，律师确认后编册。
事实核对区分事实、法律观点、请求和推测；文书事项保留段落/事项或PDF页定位。
从已复核任务进入编排时严格匹配文本及材料hash，并保留复核意见、来源任务及版本。

目录支持多材料组成一项证据、同文件复制为不同选页分项、合并/拆分、排序、可选分组和来源。
原件选页按物理页码；Word按转换后PDF页码。非法、重复、倒序或越界页不静默忽略。
页面实时重算预计编册页码，后台按真实组装结果生成目录和映射。目录摘要与证明内容分列；
Word目录独立，Excel另含内部文书对应表。文书/候选材料改变后旧草案不可直接继续编册。

审查重点与验证：
- 摘要建议只在取得可验证逐字引句时预填，否则留空提示人工补充；来源不由AI猜测。
- 摘要依据的候选片段数量可见，不宣称阅读全文或证明关联的语义准确性。
- 保存草案有版本冲突检测，刷新页面能重新载入编辑结果；编册前自动保存尚未保存的编辑。
- 缺少关联、初核矛盾/不足、否定/修正意见、选页遗漏引用不能被关联勾选掩盖，须审阅确认。
- 任务中途摘要失败可续办，不重复已完成初核与目录项；不发布部分成果。
- 预览验证案件/任务/源hash边界，直接输出页面图像，避免原生PDF插件空白。
- 专项测试覆盖分组、多材料选页、页码、文书关联伪造、跨案、材料/文书变化、续办、复核传递和版本冲突。
- 匿名真实浏览器覆盖核对→复核→转编排、原文图像、合并/拆分、选页边界、保存刷新恢复、PDF/Office下载及明暗布局。
- Word目录用文档技能与捆绑LibreOffice渲染检查；临时fontconfig只为QA加载本机中文字体，不修改用户系统或项目运行配置。

AI语义准确率、候选召回率、真实云OCR和原生WKWebView未做准确率验收。所有AI摘要、
证明内容及关联均为待审阅建议；人工勾选确认不等于系统证明事实。最大40份材料、80文书事项/目录项，
24万字材料、1500页编册。现有文书和原件均不被改写，成果留在独立任务目录。
