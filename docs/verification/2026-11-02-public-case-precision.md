# 公开互联网类案检索修复与验证

本次仅在本地 Stella 共用源码中修复，未制作或发布安装包，也未调用专业案例数据库 MCP。工作区原有大量未提交改动，均保留；未将其混入推送。

## 已定位的问题

1. “公开互联网”原先实际只有维基文库 JSON 接口，未执行研究方案中的通用网页召回。
2. 用户命题中的“发包人非所有权人”未成为必要争点；一般工程优先权案件容易进入候选。
3. 公开适配器丢弃既有支持/反对方向检索式，仅执行相近词袋；限流兜底还会删去后面的关键条件。
4. 公开案例模式仍进入本地知识库问答链路，最终输出混入本地文章。
5. 正文获取失败后，检索摘要仍可能作为案例输出，并被标成公开存档已核验。
6. 案号只从模板和标题提取，遗漏正文案号；法院说理只保留开头约700字。
7. 同案摘要可能覆盖已经取到的正文；重复IPv6回退会抛运行时异常。
8. 泛化的“予以支持/驳回”不能证明法院对用户命题的立场；诉请、抗辩也不能代替法院说理。
9. 多案例汇编可能把第一个案号错误绑定到后面其他案例的说理。
10. Python HTTP 客户端没有自动遵循 macOS 系统网页代理；部分网页请求的默认请求标识会遭维基媒体拒绝。

## 实施

- `public_case_answer.py`：公开模式提前返回，隔离本地KB及MCP；使用当前模型生成有界争点/同义词检索计划，规则中的已知硬条件不能被改写削弱。模型仅判读真实候选，支持/反对引用必须逐字命中该案法院说理；案名、案号、法院及链接由程序输出。
- `public_case_discovery.py`：Bing与搜狗公开搜索，复用已有公开地址/重定向/响应大小校验；搜索摘要只用于发现候选，读取正文后才能进入裁判候选；排除案号绑定不清的汇编。
- `public_case_web.py`：保留语义/方向查询，增加维基文库阅读页搜索和正文读取；读取正文案号及较后位置的法院说理，更新缓存版本，优先保留全文。
- `public_case_transport.py`：读取现有系统网页代理，不修改系统设置；代理连接失败可回退直连，保留明确的网络失败记录。请求标识含产品主页。
- 摘要不再当作已核验裁判；严格争点失败不再以普通工程案例填充；“所有权”这一泛词本身不再等同于“发包人非所有权人”。

## 验证

- 相关测试：56项通过，覆盖案例查询、公开案源、精度回归、直接问答及共享网页检索。
- APEX fast：通过，含语法、敏感信息及API兼容检查。
- APEX extended最终完整检查：通过；运行1289项测试，27项跳过。早先检查中出现的离线资源缓存失败在最终检查中已不再出现。
- 用户提供的维基文库阅读链接曾返回HTTP 200，取得完整裁判文字及（2022）粤07民终206号。
- 原命题真实联网检索一次召回12件去重候选，其中2件通过词项/法院说理门槛。随后以实际模型服务 Flash判读同批真实裁判：工程转让后的追及效力案件被归为部分相关，没有冒充发包时即非所有权人的直接支持；另一件未通过引文核对的候选未被列为支持。
- 最后一轮方向检索确实执行支持、反对两条独立查询，但遇到DNS失败和连接超时，未得到可用裁判。成功一次不代表网络稳定；该轮失败不代表相关案例不存在。
- 上述网络与模型检验分别执行，没有冒充整条UI流程已完成验收。未做多争点准确率基准测评，也没有证明召回穷尽或准确率已与模型服务相当。
- 本地服务曾确认source_status=current、restart_required=false。未改前端布局或原生壳。
