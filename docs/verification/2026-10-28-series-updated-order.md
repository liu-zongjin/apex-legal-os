# 系列案更新时间及外层列表排序修复

日期：2026-10-28。基线与恢复点：`41244a3`，另保留本地引用 `checkpoint/before-series-updated-order-20261028`。
分支：`fix/series-updated-order-20261028`。

## 原因与修复

- 系列单元格值、格式等变更会写入独立表或审计日志；原有审计路径没有同步更新子案、父级系列案的 updated_at。现在同一事务中更新两级时间，验证失败不更新时间。
- 之前的修改已留下较新的子案时间或系列编辑日志，但父级时间仍旧。在线列表与离线快照复用同一 SQL 时间表达式：系列取自身、子案及系列编辑日志的最近时间；普通案件沿用原值。先按置顶、有效更新时间、ID排序，再截取列表；返回的 updated_at 与排序一致。
- 历史时间聚合是读取行为，不重写既有业务记录或补造编辑时间。没有数据库结构变更或新迁移。
- 关闭系列工作台时，等已在进行中的单元格保存完成后重新加载外层列表；保留原有请求序号隔离与置顶规则。
- 离线壳统一升级291，保留IndexedDB及离线操作队列。API路径和字段结构不变。
