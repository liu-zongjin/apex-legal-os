## 前端层次与顺序

- 案件选择与功能切换分行，统一按“材料分析 → 案件时间轴 → 案件关联知识 → 核对文书事实 → 按文书编排证据”排列，各模式的导航位置保持一致。
- 工作区标题下直接进入当前任务。“分析记录”作为次要操作，展开后再显示记录；去掉默认占据整行的历史栏与“1—1”范围文案。
- 新建与结果分别呈现。查看结果时不插入收起的输入栏；新建时不同时展示旧结果，可返回结果，保留尚未提交的输入。后台状态更新不会把输入区强行收起。
- 确认区明确分为分析范围、分析目标、分析设置及授权／提交。范围展示文件数量、空状态、选择文件入口与补充文字；模型带清楚的标签与下拉提示；高级选项紧凑收起；提交集中在底部。
- 吸顶编辑区与滚动定位跟随案件栏的实际高度，避免新导航高度遮挡正文与表单。

## 已确认并修复的问题

| 问题 | 修复与验证 |
| --- | --- |
| 历史列表不返回目标，所有记录显示相同标题 | 返回最多200字符的goal；不返回完整请求配置或补充文字正文 |
| 慢速历史请求先写入半个任务对象，旧按钮可能操作新ID | 完整详情读取成功后原子切换；读取中禁用旧操作；较早响应不能覆盖后来选择 |
| 临时读取失败导致进度永久停刷 | 活跃任务继续按原周期重试；成功后清理过期错误提示；非活跃页面停止轮询 |
| 暂停期间换案件，按钮持续禁用；换功能后旧回调改变当前显示 | 控制结束后恢复当前案件；旧功能回调不改变当前功能的表单、页面状态 |
| 自动更新把已展开出处收起 | 同一任务保留各分类的出处与分析详情展开状态 |
| 模型或研究项目选项接口失败阻断历史阅读 | 选项读取独立处理；已保存结果仍能加载 |
| 补充文字没有进入材料分析，单独粘贴被拒绝 | 新任务将补充文字作为带固定哈希、片段位置的来源；支持纯文字及文件混合输入，不再额外生成逐句核对任务 |
| 页面边缘的重复正文可能被误删；OCR末行数额或份额被当作页码 | 重复不再是单独删除理由；只识别明确抬头和页标签；无坐标时保留裸数字与分数 |

## 来源兼容与保护

新增任务在请求JSON固定 `material_input_version=1`，不改变用户参数的幂等哈希。原请求标识仍返回原任务，旧任务继续使用原执行方式与固定解析缓存；没有重写历史分析或下载文件。

补充文字与文件使用同一个固定解析缓存，虚拟来源为draft-*编号，不把文字里的“第999页”当成真实物理页码。原文入口沿用原有案件／任务接口并核对文字哈希；文字被更改后拒绝继续旧解析或作为旧引用打开。审计导出保留固定文字。其他模式和关联知识的原有文书语义保留。
