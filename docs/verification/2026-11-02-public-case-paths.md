# 多路径类案检索：独立路径、候选与复核标识修复

## 本轮定位

对原问题再次进行临时匿名数据库下的完整公网检索，记录规划输出、原始正文候选、筛选后的候选和模型核验返回。未给生产查询添加固定案例号码，未用专业法律数据库 MCP。

发现四个可重现问题：

1. 模型可能只更改路径名称，必要事实仍完全相同，例如两条路径均要求“甲或乙”。这种规划不能证明两条独立路径覆盖。现检查事实集合及分支特有条件，允许一次有界修复；失败则保留完整问题，不虚报两条独立路径。
2. 整个含或问题只有一组候选分数，某分支可挤占另一分支的候选位置。现每条路径分别进行 BM25、预训练向量评分，保留全问题排序及各路径通道；法院层级/地域约束仍先执行。只有取回的候选参与此排序，未建设全网向量索引。
3. 补检查询原先合并、切片再按位置分给路径，可能把某分支的词分到另一分支。现根据实际未覆盖路径、已用查询及误检原因重新规划短查询，仅修改对应路径的检索表述，保留必要事实和路径 ID，拒绝新造案号或重复查询。
4. 独立复核输入使用对象键表示全局案例编号，模型却常把本批第一项输出为 index=0。日志记录曾对已明确选择继续履行的裁判返回 supported，却因编号不符被程序丢弃。现在每项输入显式带 index，采用数组记录，并要求原样返回。复核明确只验证当前或分支，不要求同案覆盖其他分支。

另修复跨轮覆盖：第二轮专门验证缺失路径；按案例原文身份及路径保存独立核验，一条新路径的相关/失败判断不能覆盖另一条已核验路径。输出可以在同一卡片列出分别核验的其他路径，并为已覆盖路径保留展示名额。每轮最多十二个独立复核对象，保持模型工作量有界。

候选诊断返回阶段选择标记及各路径分数。结构化输出解析只接受第一个完整根对象，允许忽略其后重复尾部，仍拒绝截断根对象，不推测补齐司法事实。

## 实际实验及失败

- 整改前独立基线约75秒，输出两件并报告两路径覆盖；但规划的两路径必要事实完全相同，且一件涉及办理手续而非明确接收，该结果不能作为稳定成功。
- 修复路径区分/排序后的中间实验仍有零命中。逐次日志进一步定位上述复核 index 错位及冗长查询问题；这些失败保留，未从报告中抹去。
- 修复后首次完整公网实验约71秒，两条路径均覆盖：已收楼路径返回（2022）粤01民终718号（已收楼并知悉事由后超过约定15日才通知解除）；继续履行路径返回（2022）粤02民终2825号（申请执行逾期交房违约金、认可达到交楼条件后又以面积差主张解除，法院认定行为矛盾）。已人工查看完整法院理由，不将附加条件删成“只要收楼就绝对不能解除”。
- 独立重新规划与检索约89秒，返回（2023）桂0204民初6074号，法院明确认定签收办证材料、确认补差面积、领取租金等行为表明已选择继续履行并接受履行，无权再解除。该次只覆盖继续履行路径，收楼路径未覆盖，并有一批模型 JSON 尾部重复导致解析失败；随后加入完整根对象解析与截断拒绝测试。此解析修复不改变已完成实验中的有效核验结论，不冒称该次覆盖了所有路径。
- 另用劳动工伤的两个或路径完整公网实测约75秒，返回七件，覆盖上下班交通事故与工作中因工受伤两条路径。人工抽查明确事实与理由的代表材料，不据此声称七件均完成独立人工法律审查。

原问题的继续履行路径在两个独立完整实验中命中不同裁判。小样本仍不足以证明整体召回稳定或穷尽；原先两个用户给定案号没有被加入生产规则，也不作为本轮必须命中的目标。

全部真实实验使用所选 模型服务 Flash 和公共来源，临时数据库，不写入用户问答，不上传用户业务资料；实验原始记录仅保存在本机临时目录，不随源码提交。没有重复修改真实历史答案。

## 恢复与验证

本地恢复点300ee31；原模块副本位于本地 .git/stella-path-before。兼容现有本地知识检索对 case_hybrid.terms 的使用，分词函数未变。具体最终自动检查数量见本轮交付。没有打包或发布安装包。

最终验证：91项案例相关测试通过；本地知识检索兼容测试14项通过（共享分词函数未改）；干净合并分支 extended 运行1329项，OK，27项环境跳过；语法、API契约、共享登记及敏感信息检查通过。
