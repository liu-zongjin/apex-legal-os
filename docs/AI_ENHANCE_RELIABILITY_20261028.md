# AI 增强与案件 AI 管理：本轮修复及验收

本轮在本地同一套 Stella 源码中实施。未制作、上传或替换公开安装包、增量包及更新订阅；不改动用户既有案件、附件、历史问答及离线队列。

## 本轮要求与处理

| 要求 | 处理 |
|---|---|
| 全面检查，不能只修截图报错 | 覆盖任务路由、上下文、资料组装、模型预算、备用模型、案件查询、文件解析、联网、视觉、流式传输、取消及恢复 |
| 普通问题和切换任务也能正常处理 | 综合问答按当前目的选择直接回答、专用检索或公开网页检索；移除“帮助”“hi”等子串误判；实质案例问题不再误作目录统计 |
| 案件 AI 的短问题不能反复超限 | 压缩并按需展开表结构，每轮重新组织有界查询结果；全部可查询表仍可发现，分页和部分字段有明确标识 |
| 法院、企业及人员简称要能查到 | 在模型规划前按原名称与去除公司、法院后缀的简称检索实际登记字段；无匹配只代表本次查询范围，无权据此推断材料不存在 |
| 正常上万字材料不应被过小应用限制拦截 | 官方 DeepSeek 的 1M 上下文核验后采用 800k 估算 token 额度，保留 20% 余量；中文/英文按文本估算，不再每个 UTF-8 字节都算一个 token |
| 不随意截掉选中的文件 | 原生文本完整读取；超过一次容量时按原顺序分批阅读所有片段，不用相关性抽样替代全文。调用前检查可完成的批次数，超出预算明确停止，不声称读完 |
| 完整提取 Word 与扫描材料 | Word 独立提取正文、表格、嵌套表格、链接文字、脚注、尾注、页眉页脚及批注；普通法律标题不再误作工作表；旧 Word 上传从保存原件修复；混合 PDF 不再因平均字数而漏掉扫描页 |
| 带文件提出联网要求，就要实际联网 | 共享文件流程按用户当前明确要求执行权威来源/公开网页检索，并将结果与文件结合；失败明确报告，不把检索建议当作已完成结果 |
| 所选模型支持视觉就智能接入 | 综合判断模型和实际接口能力：已核验模型、服务商模型元数据、自定义视觉模型声明；Chat、Responses 和 Claude Code 桥接都保留图像输入 |
| 长期记忆难读、状态与来源混乱 | 分类导航、案件名称、条目状态、完整展开、独立编辑/版本/设置；页面固定打开时案件范围；搜索分页、草稿离开提醒、请求超时、过期请求与版本冲突保护；删除同时删除对应版本内容，保留防复活指纹 |
| 节约 API 调用，提高效率 | 本地先检查 PDF 文字层，仅对必要扫描/图形页使用视觉；正常材料合并调用；有结构报告在本地提取检索结构和已有案号；已完成视觉阅读用于后续检索综合，不重复发送原页；短工作请求没有记忆/摘要任务时不追加空背景调用；多批视觉阅读中大段文字原文只发送一次，后续按批分析后综合 |
| 不能无限追加调用与重试 | 同一前台任务的主请求、嵌套模型规划与重试共享请求计数，默认最多 24 次，并为最终回答保留次数。该上限不是默认要用满的次数；普通文件问答能一次完成就只调用一次 |

## 具体缺陷

- 各来源各自截取后直接叠加，没有统一计算最终输入；备用模型容量不匹配时把整轮中断。
- 内部调用未补齐 FastAPI 默认值；模型别名和默认模型在组装上下文后才解析，预算可能错用未知模型限额。
- 案件查询反复携带完整表结构、SQL 转录和大结果，导致后续几轮持续膨胀。
- 全部案件的简称预查询结果曾只生成来源卡，却因缩进错误未进入模型输入，导致有记录仍回答查不到；已在真实模型复测中要求同时返回匹配法院、关联案件和案号，而非仅检查出现法院名。
- 长期记忆删除后仍保留可访问的版本全文、缺少删除与设置的版本检查、列表随底层案件切换、网络请求无超时、刷新失败混同保存失败等问题已修复。
- Word 问答复用了仅遍历正文段落的文章格式化器，表格内容没有进入文件问答。
- 普通 `【本院认为】` 被当成工作表定位标记。
- 上传文件路径未连接外部检索；案件文件的显式开关也无法覆盖自然语言提出的联网要求。
- 短正文没有中文句号被当成生成不完整，造成不必要的重复生成。
- 同一请求的备用模型会改写共享提示；错误/空正文和部分流式协议错误未正确进入恢复。
- 同一对话中的上下文排除没有过滤近期消息及含该消息的派生摘要。
- 已完成任务的迟到取消会覆盖完成状态；错误回答保存尚未确认就清理恢复标记。

## 验证方法

自动回归使用匿名临时数据库、合成 Word/PDF/图像及模拟外部接口。重点使用真实的资料组装、容量检查、模型调用适配和文件路由，而非把这些环节全部替换为固定答案。

新增验证包括：真实 Stella 表结构、多轮长查询、多来源大证据包、小容量备用模型、多个上万字材料完整发送、Word 嵌套表格/链接、混合 PDF OCR 同意和失败、旧上传修复、文件实际触发检索、普通 PDF 零图像请求、视觉页面完整传递、不同接口的图像格式、请求预算共享、原页图像不进入历史、短答案零误重写、流式 CRLF/末尾事件及完成后取消。

界面回归覆盖并行对话、切换与新建、草稿、逆序完成、取消确认、页面重载恢复、流式错误、兼容浏览器及自定义 API 设置。长期记忆还覆盖完整长文本、范围固定、未保存提醒、删除确认、写入成功但刷新失败、过期响应与无案件状态；1440、1024、390 像素的深浅色均检查。前端更新使用新的离线壳版本，保留业务存储。

真实 DeepSeek 服务使用隔离临时数据库与匿名合成图片验证了：普通任务切换、从完整数据库结构查询法院简称、直接视觉读取金额 783.25 及“无书面同意不得转让”的否定条件。没有上传用户真实案件或扫描原件进行这组验收。

资源效率回归确认：普通文字 PDF 为 1 次模型调用、0 张图；8 页分批视觉测试中每页仅出现在一个输入批，大段文字原文只出现一次；明显无法在预算内完成的图像任务在渲染和付费调用前拒绝。这里验证的是请求构造与调用次数，并未用用户真实案件反复调用 API 做账单对比，不能据此承诺所有任务的实际费用均低于旧版本。

## 边界

- 模型能力仍取决于实际账户、服务商接口和可用额度。自定义或未知模型没有能力元数据时，可在 AI API 管理中声明支持图像的模型 ID；不能仅凭品牌推定所有模型都支持。
- 尚未逐个使用所有服务商的真实付费账户验证；多接口协议通过匿名自动测试覆盖，真实视觉服务测试使用了 DeepSeek。
- token 计数是有余量的本地估算，真实服务商用量为准。图像请求同时受输入窗口和请求体大小约束，不能把 base64 字符数当成文本 token。
- “完整读取”表示原文片段或必要原页均已纳入处理，并不保证模型一定辨认出模糊印章、手写文字或低清扫描。无法辨认必须标明真实页码，不得猜读。
- Word 原生文字与表格已覆盖；嵌入 Word 内的独立扫描图片尚未转换成带物理页码的视觉页面。
- 超大型任务超过本次自动请求预算时明确停止，不截掉材料后假称完成；分批分析结果本身仍超过窗口时按批交付，并明确尚未形成跨批统一结论。
